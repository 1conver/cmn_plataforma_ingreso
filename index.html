Trampas frecuentes de examen
REPASAR ANTES DE RENDIR
Switch vs Router. El switch segmenta dominios de colisión; solo el router (o VLAN) segmenta broadcast.
Distancias administrativas. Estática 1 · EIGRP 90 · OSPF 110 · RIP 120. RIP: máx. 15 saltos, 16 = inalcanzable.
Share + NTFS. Por red rige el permiso más restrictivo; en local solo NTFS. Un Denegar explícito gana.
FSMO. 2 por bosque (Schema, Domain Naming) y 3 por dominio (RID, PDC, Infrastructure).
AGDLP. Cuentas → Globales → Locales de dominio → Permisos. Los permisos van al grupo Local.
4FN vs 5FN. 4FN elimina dependencias multivaluadas; 5FN (Fagin) las de unión.
WHERE vs HAVING. WHERE filtra filas antes de agrupar; HAVING filtra grupos. TRUNCATE no admite WHERE.
Hosts por subred. Útiles = 2n − 2 (n = bits de host). Un /30 tiene 2 hosts útiles.
ASP y PHP. Application es global; Session, por usuario. mysql_pconnect reutiliza la conexión.

PILAR A Redes y Telecomunicaciones Uyless Black • Castro Lechtaler • CCNA
Ver síntesis
// MODELO OSI Y DISPOSITIVOS • Capa 1 (Física): Repetidor, Hub. Mismo dominio de colisión y de difusión. • Capa 2 (Enlace): Switch, Bridge. Segmenta colisiones vía tabla CAM/MAC. FCS (CRC-32): descarte silencioso de tramas corruptas en store-and-forward. • Capa 3 (Red): Router. Delimita dominios de broadcast por interfaz. • Capa 4 (Transporte): TCP (3-Way Handshake SYN / SYN-ACK / ACK, ventana deslizante) y UDP (sin conexión). • PDUs: Bit → Trama → Paquete → Segmento → Datos.
// ENRUTAMIENTO Y WAN • Distancias administrativas: Conectada(0), Estática(1), EIGRP(90), OSPF(110), RIP(120). • RIP: vector distancia, métrica saltos (máx 15), Split Horizon / Poison Reverse. • OSPF: estado de enlace, Dijkstra (SPF), áreas jerárquicas (Área 0 backbone), métrica por costo. • Frame Relay: NBMA, PVC identificado por DLCI local, LMI (señalización), CIR, FECN/BECN. • PPP: LCP (enlace, autenticación, compresión) + NCP (encapsula Capa 3). PAP (plano) vs CHAP (MD5, 3 vías). • HDLC: orientado a bits; la versión Cisco es propietaria.
// CABLEADO • UTP: RJ-45, normas T568A/T568B, 100 m, categorías 5e/6, diafonía (crosstalk). Directo PC-Switch; cruzado entre iguales. • Coaxial: 10BASE2 (185 m) y 10BASE5 (500 m), bus con terminadores (histórico). • Fibra: Monomodo (láser, WAN, km) vs Multimodo (LED, campus LAN). Inmune a EMI. • Inalámbricas 802.11: a (5 GHz), b (11 Mbps), g (54 Mbps), n/ac (MIMO, mayor throughput).
// IPv4 Y SUBNETEO • Clases: A (/8), B (/16), C (/24). Loopback 127/8. • RFC 1918: 10/8, 172.16/12, 192.168/16. • Octeto crítico: salto = 256 - valor de máscara. Red = bloque inmediato inferior; broadcast = siguiente red - 1. • Hosts útiles: 2ⁿ - 2. • Ejemplo /22: 172.16.89.45 → Red 172.16.88.0, Broadcast 172.16.91.255, 1022 hosts.
PILAR B Sistemas Operativos • Windows Server Curricula Microsoft • TechNet
Ver síntesis
// ACTIVE DIRECTORY: ESTRUCTURA • DC: servidor con AD DS + NTDS.dit + Kerberos v5. • Árbol: dominios con espacio DNS contiguo; confianzas transitivas. • Bosque: frontera de seguridad; un Esquema y un Catálogo Global comunes. • Sitios: subredes IP de alta velocidad. Intra-sitio: RPC notificado, ~5 min, sin comprimir. Inter-sitio: programado, comprimido (RPC sobre IP o SMTP para Esquema/Config). • FSMO Bosque (1): Schema Master, Domain Naming Master. • FSMO Dominio (1 por dom): RID, PDC Emulator (hora SNTP), Infrastructure.
// CUENTAS, GRUPOS Y PERMISOS • AGDLP: Cuentas → Grupos Globales (rol) → Grupos Locales de Dominio (recurso) → Permisos. • Grupos: Global (mismo dominio), DL (cualquier dominio confiable, recibe permisos), Universal (bosque, requiere GC). • Share vs NTFS: por red rige la intersección más restrictiva. Denegar explícito invalida Permitir. • Auditoría: GPO "Auditar acceso a objetos" + Seguridad → Opciones avanzadas → Auditoría → eventos en el Registro de Seguridad. • Impresoras: compartir, drivers x86/x64, permisos (Imprimir / Administrar documentos / Administrar impresoras), pool y prioridades.
// SERVICIOS DE RED • DNS: zonas integradas en AD, registros A / PTR / SRV (_ldap._tcp, _kerberos) / CNAME; actualización dinámica segura. • WINS: NetBIOS→IP para legados; nodos b / p / m / h (h = híbrido, por defecto). • DHCP: DORA (Discover, Offer, Request, Ack); reservas por MAC, exclusiones, opciones 003/006/015; DDNS registra A y PTR. • RRAS: enrutamiento + NAT + acceso remoto. • VPN: PPTP (TCP 1723 + GRE, MPPE débil) vs L2TP/IPSec (UDP 1701 + ESP AES/HMAC, requiere certificado o PSK). • RADIUS/NPS: AAA centralizado; 802.1X. • DFS: Namespaces (árbol unificado, failover) + Replication (DFS-R, bloques RDC).
PILAR C Desarrollo de Software & Paradigmas Eslava Muñoz • UML • ASP IIS
Ver síntesis
// TRADUCTORES Y PARADIGMAS • Compilador: traduce todo antes de ejecutar; genera binario autónomo. Fases: léxico → sintáctico (AST) → semántico → optimización → código objeto. • Intérprete: traduce y ejecuta línea a línea en tiempo real. • Linker/Compaginador: resuelve referencias cruzadas y ensambla el ejecutable (librerías estáticas vs DLL dinámicas). • 6 Paradigmas: Imperativo (estado secuencial), Funcional (pureza, inmutabilidad), Lógico (unificación, Prolog), Heurístico (aproximación NP-hard), Concurrente (semáforos, monitores, deadlock), POO (encapsulamiento, herencia, polimorfismo).
// HISTORIA Y ESTRUCTURADA • Hitos: FORTRAN 1957 (científico compilado) · LISP 1958 (funcional) · COBOL 1959 (comercial) · ALGOL 60 (sintaxis moderna) · BASIC 1964 · Pascal 1970 · C 1972 (UNIX) · SQL 1974 · C++ 1983 · Java/JS/PHP 1995 · C# 2000. • Programación estructurada: Dijkstra ("GOTO harmful", 1968) + Teorema de Böhm-Jacopini: secuencia, selección e iteración. Top-down, alta cohesión, bajo acoplamiento.
// WEB CLÁSICA: PHP Y ASP • Nacimiento: Berners-Lee (CERN 1989-91): HTML + HTTP + URL. Mosaic 1993 populariza la web. • DHTML: HTML + CSS + JavaScript + DOM (no es estándar, es una combinación). • PHP + MySQL: mysql_connect() cierra el socket al terminar el script; mysql_pconnect() mantiene la conexión en el pool de Apache (sin nuevo handshake). • ASP clásico: Application (global a todas las sesiones, con Lock/Unlock) vs Session (privada por usuario, timeout 20 min); Request/Response/Server completan los objetos intrínsecos.
PILAR D Bases de Datos & SQL Nevado Cabello • Jiménez Capel • Prescott
Ver síntesis
// E-R Y MODELO RELACIONAL • Etapas: Conceptual (E-R) → Lógico (relacional) → Físico (índices, particiones). • Grado: unaria (reflexiva), binaria, ternaria, N-aria. • Cardinalidad: 1:1 (PK compartida o FK única), 1:N (FK del lado N), N:M (tabla puente). • Atributo derivado: se calcula de otros (edad desde fecha de nacimiento). • Relacional: tabla = relación, fila = tupla, columna = atributo; dominio = valores válidos; vistas = tablas virtuales. • Integridades: entidad (PK no nula), referencial (FK), dominio (CHECK).
// 1FN A 5FN EXHAUSTIVA • 1FN: valores atómicos, sin grupos repetitivos, PK obligatoria. • 2FN: 1FN + sin dependencias parciales de clave compuesta. • 3FN: 2FN + sin transitivas (no-clave no determina no-clave). • BCNF: todo determinante es superclave. • 4FN (MVD): suprime X ↠ Y independientes dividiendo en 2 tablas binarias. • 5FN (PJNF): dependencias de unión cíclicas ternarias: 3 proyecciones binarias sin tuplas espurias (Teorema de Fagin).
// T-SQL • Clustered Index: orden físico real en disco, hojas = datos (máx 1, se crea con la PK). Non-Clustered: B+ independiente, hojas = RID/clave (hasta 999). • WHERE filtra filas; HAVING filtra grupos (después de GROUP BY). • DELETE vs TRUNCATE: DELETE fila por fila al log, admite WHERE, dispara triggers; TRUNCATE desasigna páginas, reinicia IDENTITY, sin WHERE, mínimo registro, no si hay FK referenciando. • Transacciones: BEGIN/COMMIT/ROLLBACK; @@ERROR clásico o TRY/CATCH; ACID (Atomicidad, Consistencia, Aislamiento, Durabilidad). • Vistas: CREATE VIEW — seguridad (ocultar columnas) y simplificación.

Cómo estudiar para que se quede
No existe la memoria fotográfica real. Lo que se parece: convertir el dato en una imagen vívida y absurda, y ubicarla en un lugar conocido.
Palacio de la memoria. Recorré tu casa: 7 habitaciones = 7 capas OSI, con la capa 1 en la puerta de calle y un objeto exagerado en cada una.
Espaciado. Repasá a 1, 2, 4, 8 y 16 días: la app te trae cada ítem cuando está por olvidarse.
Mezclá temas. Alternar redes, Windows y SQL en una misma sesión cuesta más pero se retiene mejor que bloques largos de un solo tema.
Dibujá de memoria. Un esquema de OSI, de un bosque de AD o de un E-R en papel en blanco, y recién después comparalo.
Dormí. El sueño consolida: repasá 10 minutos antes de dormir y a la mañana, otra vez, sin mirar.
